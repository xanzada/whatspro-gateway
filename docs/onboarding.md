# Жаңа фаст-фуд желісін қосу

Бір ресторан = NocoDB кестесіндегі бір жол + WhatsApp сессиясы. Басқа ештеңе жоқ:
код өзгертілмейді, деплой қажет емес, бот қайта іске қосылмайды. Кестеге жол
қосқаннан кейін ең көбі 5 минут ішінде (кэш мерзімі) жаңа ресторан тірі болады.

## Қадамдар

1. **NocoDB кестесіне жол қосу** — төмендегі бағандарды толтырыңыз.
2. **WhatsApp сессиясын ашу** — `/whatspro` бетінен instance қосып, QR-кодты сканерлеу.
3. **Тексеру** — `/tenants` бетін ашыңыз. Бәрі жасыл болса, ресторан жұмысқа дайын.

`/tenants` беті кестені оқып, әр жолды тексереді және «дайын емес» деп тұрса
нақты қай баған жетіспейтінін көрсетеді. Сол бетті ашпай тұрып ештеңені
клиентке бермеңіз.

## Міндетті бағандар

Біреуі болмаса — ресторан жұмыс істемейді. `/tenants` оны қызылмен көрсетеді.

| Баған | Мәні | Болмаса не болады |
| --- | --- | --- |
| `instance_id` | `prestige` сияқты қысқа латын атауы (`A-Z a-z 0-9 _ -`, 2–64 таңба) | Ресторан жүйеде мүлдем жоқ. Барлық Redis кілттері, чат, сигналдар осы бойынша бөлінеді |
| `whatsapp_phone` | Ботқа тиесілі WhatsApp нөмірі, тек цифр: `77015550101` | Кіріс хабар қай ресторанға тиесілі екені белгісіз — бот үндемейді |
| `domain` | DLE сайтының домені: `prestige.kz` немесе `https://prestige.kz` | Мәзір, тапсырыс күйі, ас үй параметрлері, SOS сигналы — ешқайсысы жүрмейді |
| `whatspro_base_url` | WhatsPro шлюзінің толық мекенжайы: `https://wa.bekaba.com` | Агент жауап жазады, бірақ клиент оны алмайды |
| `whatspro_api_token` | Осы ресторанға ғана арналған кездейсоқ токен, ≥ 24 таңба | Бот хабар жібере алмайды, оператор чатты аша алмайды |
| `system_prompt` | Агенттің мінезі, ережелері, осы ресторан туралы фактілер (≥ 200 таңба) | Бот жалпы жауап береді, ресторанды білмейді |
| `webhook_secret` | Сайттан келетін сигналдарды растайтын құпия сөз, ≥ 16 таңба | Сайттың сигналдары қабылданбайды |

**`whatspro_api_token` туралы маңызды ескерту.** Бұл токен енді екі жаққа да
жұмыс істейді: бот сол арқылы хабар жібереді, әрі ресторан сол арқылы **тек өз**
чатын ашады. Сондықтан ол әр ресторанда **бөлек** болуы керек. Екі ресторан бір
токенді бөлісіп тұрса, бірі екіншісінің чатын оқи алады — `/tenants` мұны
«қақтығыс» деп қызылмен көрсетеді.

Токен жасау:

```bash
openssl rand -hex 24
```

## Толықтыратын бағандар

Болмаса да бот жұмыс істейді, бірақ кейбір сұраққа нашар жауап береді.
`/tenants` оларды сарымен көрсетеді.

| Баған | Не үшін керек |
| --- | --- |
| `brand` | Оператор чатының тақырыбы және агент айтатын атау |
| `work_hours` | «Қашан ашықсыңдар?» сұрағының жауабы |
| `address` | Өзі келіп алу және мекенжай сұрақтары |
| `dev_phone` | Техникалық ақау болғанда ескерту осы нөмірге кетеді |
| `kanban_secret` | Kanban/CRM арнасының кілті — тапсырыс тақтасының оқиғалары |

## Ресторандар арасындағы қақтығыс

Бір жолды жеке қарап тұрып көрінбейтін, бірақ 50 ресторанда ең қауіпті үш қате.
`/tenants` беті кестенің бәрін салыстырып, осыларды бөлек блокпен шығарады:

- **бір `whatsapp_phone` екі жолда** — клиенттің хабары басқа ресторанға түседі;
- **бір `whatspro_api_token` екі жолда** — бір ресторан екіншісінің чатын ашады;
- **бір `instance_id` екі жолда** — қай жол оқылатыны кепілдендірілмейді.

Бұлардың бірі шықса, екі ресторан да «дайын емес» болып саналады.

## API арқылы тексеру

Бет ашпай, скрипттен тексеру керек болса:

```bash
curl -H "x-api-key: $WHATSPRO_API_TOKEN" https://wa.bekaba.com/api/wa/tenants
curl -H "x-api-key: $WHATSPRO_API_TOKEN" https://wa.bekaba.com/api/wa/tenants/prestige
```

Екеуі де тек платформа токенімен ашылады (ресторанның өз токенімен емес) және
жауапта ешқандай құпия мән қайтпайды — тек `OK` / `MISSING` / `INVALID` кодтары.

## Жол қосқаннан кейін

NocoDB оқулары кэштеледі, сондықтан өзгеріс бірден емес, шамамен **5 минут**
ішінде күшіне енеді (`NOCODB_CONFIG_CACHE_MS`). Жаңа жолды сол уақыт өткен соң
`/tenants` бетінен қайта тексеріңіз.
